# pUZlink — conventions for Claude Code

- The spec is `docs/pOZle_color-link_spec_v1.0.md`. It is the source of truth. If code and spec disagree, the spec wins; if the spec is ambiguous or wrong, stop and ask rather than guess.
- Build in the phase order of spec section 17. Do not start a phase until the previous phase's definition of done is met. Report at each milestone.
- `src/engine/**` and `src/generator/**` are pure TypeScript: no DOM, no `window`, no `Math.random`, no imports from `app/`, `render/`, `input/`.
- TypeScript strict mode; no `any`; no `// @ts-ignore`.
- Tests live in `tests/` mirroring `src/`. Every rule in spec 5.2 has a named test. Run `npm test` before every commit; never commit red.
- Tests run in the `node` environment by default. A test that needs a DOM opts in per file with a `@vitest-environment jsdom` docblock at the top. jsdom has no canvas and no layout, so anything touching `BoardRenderer` belongs in the browser checks instead.
- `npm run verify` drives a headless browser through the app and checks the acceptance criteria in spec 12 that can only be judged by running it (the "(R)" rows). It starts its own dev server. It needs a Chromium-based browser; set `CHROME_PATH` if it cannot find one. Run it after any change to `app/`, `render/` or `input/`.
- `npm run verify:pwa` builds and checks the phase 6 work: manifest, icons, service worker, and a real offline reload with the server stopped. Run it after any change to `index.html`, `vite.config.ts`, `src/app/pwa.ts` or the icons.
- `MainActivity.java` runs the app edge to edge with transparent system bars, and hides the navigation bar while the app is in front — re-hiding it on every focus change, because Android drops the request whenever the window loses focus. A swipe from the bottom edge brings it back transiently. The status bar stays visible over the artwork.
- Because of that, the page must keep clear of the status bar itself. `env(safe-area-inset-top)` is filled from the display cutout on Android and reads 0 on most phones, so `MainActivity` measures the real inset and sets `--inset-top` on the root element; the stylesheet defaults it to `env()` for the web and iOS, `#app` pads by it, and the Home masthead subtracts it from its own top padding rather than stacking with it.
- `npm run apk` builds the Android debug APK: web bundle in native mode, `cap sync`, then Gradle. Needs the Android SDK with `ANDROID_HOME` set and a JDK of 21 or older on `JAVA_HOME` — Gradle 8.11.1 rejects the JDK 25 that current Android Studio bundles ("Unsupported class file major version 69"); `/usr/libexec/java_home -V` lists what is installed. The APK lands in `android/app/build/outputs/apk/debug/`.
- The native bundle is built with `--mode native`, which drops the service worker. Capacitor serves every app version from the same `https://localhost` origin, so a worker from an older install would shadow a freshly installed APK. Do not add the PWA plugin back to that mode.
- `npm run android:open` builds the native bundle, `cap sync`s it and opens `android/` in Android Studio, which then owns the Gradle build and the device. It needs neither a JDK on the `PATH` nor `ANDROID_HOME`; `-- --open-only` skips the rebuild.
- `npm run icons` also writes the Android launcher icons into `android/app/src/main/res/mipmap-*`. Re-run it after editing the artwork, then rebuild the APK.
- `npm run unlock:device` seeds the gate tiers on a connected phone over adb, so the later tiers can be tested without playing 20 levels first. It needs the app open and its WebView forwarded to port 9222. It backs up the phone's progress first; `-- --restore` puts it back.
- Anything that only exists on a device — haptics, the Android back button, the launcher icon, the hidden navigation bar — has to be checked on the device. Both have been reported working from a green browser suite and been wrong: `navigator.vibrate` returns true without the VIBRATE permission, and Capacitor ships no back handling at all.
- The background artwork behind every screen is `public/textures/backdrop.webp`, a lossless re-encode of Tob's file in `../Specs/images/`. It is used exactly as supplied: never crop, tint, lighten, darken or scrim it. `python3 scripts/textures/prepare-background.py` rebuilds it and refuses to write anything that is not pixel-identical to the source; `--check` verifies the committed file.
- The artwork is lit from below, so there are two inks and an element takes the one for the region it sits in: `--ink-on-art` + `--ink-shadow` (white, up top) or `--ink-on-lit-art` + `--ink-lit-shadow` (navy, down in the light), with `--ink-lit-shadow-heavy` for the 12-14px stats and toolbar and `--ink-drop` / `--ink-lit-drop` for SVG icons. Neither ink follows the theme. Anything with a surface of its own — the board, a modal card, a tier capsule, a level tile — keeps its own ground instead. A `<button>` inherits neither the outline nor the colour, so name it explicitly. If the artwork is ever swapped again, re-measure: whether one ink or two serve the screen is a property of the picture.
- The PNG icons in `public/` are generated by `npm run icons` from the artwork in `scripts/icons/generate.mjs`. Edit the artwork there and re-run; do not hand-edit the PNGs.
- Formatting: Prettier defaults (`.prettierrc`: `{ "singleQuote": true, "semi": true }`). Run `npm run format` before committing.
- Dependencies: only those in spec 11.4. Ask before adding anything.
- All user-facing text goes through `src/app/strings.ts`. All tunables go in `src/app/config.ts` or `src/generator/difficulty.ts`.
- Commit at the end of every phase with a message `phase N: <milestone name>`; smaller commits within a phase are welcome.
- Never bump `GENERATOR_VERSION` without adding a changelog line to the spec and telling Tob.
